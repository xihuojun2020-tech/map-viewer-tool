# 自行部署地图查看工具

服务器部分全部在 `backend/`，地图编译入口为 `scripts/compile_layer.mjs`。实际运行配置、模型密钥、访问凭据、小说全文、数据库、取文身份池和日志不属于公开源码。

## 运行环境与目录

参考环境为 Ubuntu 24.04、Python 3.10+、Node.js 22、Nginx 和 systemd。后端仅使用 Python 标准库。Node 不需要安装额外 npm 依赖，只运行已有场景编译模块。

| 文件或目录 | 作用 |
|---|---|
| `/opt/map-tool/backend/` | 仓库 `backend/` 的全部 Python 文件 |
| `/opt/map-tool/compiler/scripts/compile_layer.mjs` | 编译入口 |
| `/opt/map-tool/compiler/web/scene/` | 完整场景模块目录 |
| `/opt/map-tool/compiler/web/atlas.json` | 地名及史料资料 |
| `/opt/map-tool/compiler/web/strategic-regions.json` | 共享底图区块 |
| `/var/lib/map-tool/` | 运行数据库、分析断点与剧情包，私有 |
| `/etc/map-tool/service.env` | 模型密钥与托管访问凭据，私有 |
| `/etc/map-tool/source.env` | 本机取文接口凭据，私有 |
| `/srv/map-tool/releases/` | 经校验的安装包和签名更新清单 |

创建专用系统用户 `map-tool`；状态目录由该用户拥有，代码目录只读。将两个 `.env.example` 模板复制到 `/etc/map-tool/`，权限设为 `600`，填写自己的配置。`MAPTOOL_API_KEY` 为 OpenCode Go 的模型密钥，`MAPTOOL_ACCESS_TOKEN` 为本部署的初始访问凭据；不要复用或索取维护者的真实值。

当前模型协议使用 `backend/analysis.py` 中明确指定的官方接口和模型。若替换供应商，需核对其请求字段与响应格式，再运行对应协议测试。

## 可选书源服务

固定上游见 `source.lock.json`。从该上游取得代码，检出所列提交，保留其 LICENSE 和 README。源码未作私有修改，地图后端只调用其搜索、目录和章节接口。

```sh
cargo build --release --locked --bin fqapi-server
```

Windows 到 Linux 的已验证交叉构建方式为：

```sh
cargo zigbuild --release --locked --target x86_64-unknown-linux-gnu --bin fqapi-server
```

运行环境和构建版本参考 `source.lock.json`；哈希是原有交付二进制的记录，不保证不同工具链重建逐字相同。

将程序放在 `map-source.service` 的 ExecStart 所指目录，创建独立 `map-source` 系统用户与 `/var/lib/map-tool-source` 状态目录。`FQ_API_TOKENS` 与 `MAPTOOL_SOURCE_TOKEN` 使用相同的新随机令牌。上游默认拒绝无鉴权启动；不要开启匿名读取。

该组件监听 `127.0.0.1:18921`，地图 API 监听 `127.0.0.1:18791`。取文状态中的 `pool.key` 和身份资料必须一起私密备份，不提交 Git，不作为静态网站目录公开。

## 服务启动

把 `map-tool.service` 和 `map-source.service` 复制到 systemd 单元目录。根据自己的 Node 安装位置修改 `MAPTOOL_NODE`，不要照抄不存在的运行时路径。

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now map-source map-tool
curl --fail http://127.0.0.1:18921/readyz
curl --fail http://127.0.0.1:18791/health
```

Nginx 的 location 示例为 `map-tool.nginx.conf`，应放入自己已配置证书的 HTTPS server 中。它不包含域名、SSH 登录或证书私钥。客户端目前有明确的服务器地址与更新域名校验，自行部署时要同步修改客户端地址。

单个地图 API 服务限制 256 MiB，取文服务限制 128 MiB；编译串行、按需启动，Node 堆上限 96 MiB。模型请求调用外部接口，不在这台机器加载模型权重。首次上线先用自己的短示例验证，按实际负载调整，不把示例限制当作容量保证。

## 凭据、升级与备份

新增安装凭据使用 `scripts/issue_library_token.py`，凭据输出到私有文件，数据库只保存摘要。不同用户的私有任务不可共享；公共来源的同范围任务可以复用。

升级前用 SQLite backup API 备份数据库，保留旧代码、私有配置、取文状态及旧发布清单。先发布不可变安装包并校验，再切换签名更新清单。不要直接用旧数据库覆盖新数据库，避免丢失新增用户请求。

独立运营者必须使用自己的 APK 签名和更新签名密钥；仓库只提供更新验签公钥。修改公钥与客户端地址后，使用 `scripts/make_android_update.py` 生成自己的发布清单。私钥保存在仓库外，密码通过私有环境传入。
